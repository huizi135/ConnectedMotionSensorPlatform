Connected Motion Sensor Platform · 中文学习手册

用烘焙理解运动传感器平台

整理日期：2026 年 10 月 23 日 · 内容来源：本项目对话中的完整术语讲解 · 可离线阅读与浏览器打印

Mosquitto 是一个实现 MQTT 协议的消息中转服务器，也叫 MQTT Broker。在你的项目里，模拟传感器把读数交给它，后端订阅这些读数，Mosquitto 就负责转交。

我们把整个项目想象成一间配有温度计、烤箱和实验记录的烘焙工作室。技术名词会更容易串起来。不过类比只是帮助理解，不能替代实际的数据与故障规则。

先看工作室怎样运转

假设你正在比较三次肉桂卷实验，持续记录面团温度和烤箱状态：

烘焙工作室我们的项目
温度计不断测量传感器不断产生数据
测量员按统一格式填写读数模拟器生成符合契约的消息
按类别投递读数的收发台Mosquitto
收发台的投递规则MQTT
接收并检查读数的实验助理.NET Consumer
实验记录档案柜PostgreSQL
查询记录的窗口REST API
工作室仪表盘Grafana

MQTT 是通信规则，Mosquitto 是执行这些规则的软件。就像“按编号接单和分发”是一套规则，而收发台是实际执行它的地方。

模拟传感器→Mosquitto→.NET 处理→PostgreSQL→API 与展示

这条链路是计划架构，不能将图中模块视为已实现。当前处于 Phase 1 环境准备。

1 数据从哪里来

技术名字实际含义烘焙类比
Sensor 传感器测量物理现象的设备。测量面团温度的探针。
IMU 惯性测量单元通常包含加速度计和陀螺仪。贴在搅拌盆上的运动测量器。
Accelerometer 加速度计测量加速度，读数也涉及重力。感知盆子被提起、晃动或放下。
Gyroscope 陀螺仪测量角速度。感知盆子旋转得多快。
ESP32可连接传感器、运行程序并通信的微控制器。给测量工具配的一颗小型控制“大脑”。
Virtual Sensor 模拟器用软件生成传感器读数。没有温度探针时，先生成一组升温、降温曲线测试记录系统。

目前我们只有软件模拟这一条路径。Python 模拟器将生成 Idle、Motion、Jump、Landing 场景，尚未测量任何真实运动。

2 数据怎样传递

技术名字实际含义烘焙类比
BLE低功耗蓝牙，适合设备间的近距离通信。无线温度探针向旁边接收器传读数。
GATTBLE 中组织和访问设备数据的方式。规定探针提供“温度”“电量”等哪些可读取项目。
Gateway 网关连接不同通信方式并转换数据的程序或设备。把探针专用读数转换成工作室统一记录格式的接收器。
MQTT发布、订阅消息的通信协议。测量员投递读数，感兴趣的人提前登记要接收哪类读数。
Broker接收发布、管理订阅并路由消息的服务器角色。工作室的消息收发台。
Mosquitto一款实现 MQTT 协议的 Broker 软件。我们选用的具体收发台。
Publish 发布向某个 Topic 发送消息。把“烤箱 1 的温度读数”交到对应栏目。
Subscribe 订阅登记希望收到哪些 Topic 的消息。实验助理登记接收所有烤箱温度读数。

Mosquitto 的价值在于，测量员不用逐个联系接收者。记录程序可以接收数据，调试程序同时观察，后续分析程序也可以接收同一类消息。

发布者只需要知道收发台在哪里、向哪个 Topic 发布，无须知道后面有几个接收者。MQTT 是通信规则；Mosquitto 是执行这些规则的软件。

3 MQTT 里的几个重要词

名字烘焙类比实际要点
Topic工作室/烤箱1/温度栏目。消息的路由名称，不是数据库表。
Payload纸条上的“12:00，180°C”。消息正文。
QoS 0交一次纸条，不要求协议确认。可能丢失。
QoS 1按协议确认投递，必要时重发。接收者可能收到重复消息。
QoS 2使用更多协议步骤避免同一次协议投递重复。仍不等于业务已经成功入库。
Retain栏目保留最新一张状态牌。新订阅者可收到最近保留的消息，不是历史记录。
Keep Alive定期确认“测量员还在联系”。用于检测连接是否失联。
Last Will 遗嘱消息提前留下“我意外失联时，请挂出离线牌”。Broker 在符合条件的异常断线后发布预设消息。

例如，我们会保留设备状态 online/offline，但不会保留每条运动读数。

收发台确认收到了纸条，不代表实验助理已经把它写入档案柜。这就是为什么我们一直区分 MQTT QoS 和数据库持久化。

4 大家如何看懂纸条

技术名字实际含义烘焙类比
JSON一种文本数据表示格式。大家都能读取的标准记录单。
Message Contract 消息契约字段、单位、身份、时间等约定。规定温度必须标明单位、每次实验必须有编号。
JSON Schema可由程序执行的结构校验规则。检查记录单必填项和类型的规则表。
Validation 校验根据规则检查输入。检查有没有漏写时间、把温度填成文字。
Schema Version消息规则的版本。第一版记录单和第二版记录单，不能混用字段含义。

我们的一条消息大致相当于下面的记录片段：

{
  "deviceId": "sim-001",
  "sequence": 42,
  "sampledAt": "2026-10-23T10:00:00Z"
}

三个身份各自回答什么问题

字段烘焙类比
messageId这张读数单的唯一编号，复印重交时编号不变。
streamId这一次连续测量任务的编号。
sequence该任务内第 0、1、2……张读数单。

上面是便于理解的字段片段，不是完整合法消息；完整示例见 contracts/mqtt/v1/examples/telemetry.json。

streamId 不是“一份肉桂卷配方”的编号，也不是业务上的训练会话编号。

5 谁处理数据

技术名字实际含义烘焙类比
Python编程语言，适合信号生成、脚本和分析。便于快速编写实验计算方法的工具。
C#我们编写核心后端的语言。编写工作室正式操作流程的语言。
.NET运行 C# 程序的运行时和开发平台。支撑这些操作流程运行的整套工作设施。
Consumer 消费者接收消息并执行处理的程序。领取读数、检查并记录的实验助理。
Worker Service / BackgroundService持续在后台工作的 .NET 程序或组件。不等顾客开口，一直处理新到读数的助理。
ASP.NET Core .NET 的 Web 应用框架。建立查询窗口所用的设施。
REST API通过 HTTP 暴露资源和操作的接口。“查询设备”“查看昨天记录”的标准服务窗口。
MQTTnet .NET 使用的 MQTT 客户端库。让 C# 助理能使用 MQTT 收发台的工具。
paho-mqttPython 使用的 MQTT 客户端库。让 Python 模拟器能向同一个收发台投稿的工具。

C# 是语言，.NET 是平台，ASP.NET Core 是其中用于 Web 开发的框架。

我们初期把后台处理和 API 放在一个 .NET 进程里，但内部明确分工，这就是模块化单体。像一间工作室里分设收货、记录和查询岗位，不需要一开始就为每个岗位租一栋楼。

6 数据怎样保存与查找

技术名字实际含义烘焙类比
PostgreSQL关系型数据库软件。管理实验记录的档案系统。
SQL查询和操作关系数据的语言。“找出昨天烤箱 1 的所有温度记录”的查询方式。
Table 表按字段组织的一组记录。设备登记册、采样记录册。
Index 索引加快特定查询的数据结构。按设备和日期建立的检索目录。
Transaction 事务将一组数据库操作作为一个整体提交或回滚。要么完整登记这次操作，要么撤回，避免只记一半。
Unique Constraint 唯一约束禁止重复的身份组合。同一张读数单编号不能登记成两条独立记录。
Migration 迁移有版本地修改数据库结构。给记录册增加一栏，同时保存改版步骤。
Pagination 分页分批返回查询结果。一次取 100 条记录，而不是搬出整个档案柜。

数据库表结构和 JSON Schema 都可能被叫作“Schema”，但它们分别约束存储结构和消息结构，不是同一个东西。

7 出故障怎么办

技术名字烘焙类比实际含义
Buffer 缓冲暂时堆放未登记读数单的托盘。吸收接收与处理速度的差异。
Bounded Queue 有界队列只能放 100 张纸的托盘。容量有限，避免内存无限增长。
Retry 重试档案柜暂时打不开，稍后再试。对可恢复失败再次执行操作。
Idempotency 幂等同编号纸条交两次，档案只登记一次。重复执行不产生额外业务结果。
Backpressure 背压托盘已满，请上游减速或等待。把处理能力限制反馈给接收链路。
Persistence 持久化正式保存到可恢复的档案里。不只是保存在进程内存中。

“托盘里的纸”对应内存缓冲：程序崩溃后可能丢失。因此增加 Buffer 不能自动解决可靠性，仍要明确队列满了怎么办、何时确认消息，以及怎样处理重试。

8 工作室怎么搬到另一台电脑

技术名字实际含义烘焙类比
Docker Image 镜像应用与依赖的打包模板。一套标明设备型号、配件及运行要求的标准工作站方案。
Container 容器从镜像启动的运行实例。根据方案实际运行的一台工作站。
Docker DesktopWindows 上管理容器的应用。工作站管理控制台。
Docker Compose用配置描述和启动多个服务。一张安排收发台、档案柜和仪表盘的工作室布置单。
Volume 卷容器外独立管理的持久数据存储。工作站更换后仍要保留的记录柜。
WSL2Windows 上的 Linux 内核运行环境。为 Linux 工作站提供所需基础设施。
Ubuntu一种 Linux 发行版。一套供你亲自操作的完整 Linux 工作环境。

我们选择 Windows 本机运行 Python/.NET，Docker 运行基础服务，因此你目前不必额外安装 Ubuntu。

另一个名字 .venv 只是 Python 依赖隔离环境，相当于为某个实验准备专用工具包；它没有容器那样的进程和系统环境隔离能力。

容器可以删除重建；需要保留的数据要另外配置持久化存储。Docker 本身不会自动保证数据库数据不丢失。

9 怎样知道系统是否健康

技术名字实际含义烘焙类比
Logging 日志记录具体运行事件。“12:01，读数单 42 保存失败”。
Structured Logging 结构化日志将事件拆成可查询字段。时间、设备、消息编号、错误类型分别填写。
Metrics 指标随时间变化的数值。每分钟处理量、错误次数、等待时间。
Prometheus收集和保存运行指标的系统。定时抄录工作室运转数据的记录员。
Grafana查询和展示数据的仪表盘工具。展示吞吐、错误率、趋势的看板。
Health Check 健康检查检查服务状态的接口。检查岗位是否能工作。
Liveness / Readiness进程活着／已具备处理条件。“助理还在岗”／“档案柜已打开，可以接活”。

日志帮助你解释某次失败发生了什么；指标帮助你观察失败是否越来越频繁。

Grafana 可以展示运行健康，也可以展示业务趋势，但数据来源和计算方式需要分别设计。

10 怎样证明有效

技术名字实际含义烘焙类比
pytest / xUnitPython / .NET 测试框架。自动检查实验工具和流程是否符合预期。
Unit Test 单元测试检查较小的独立逻辑。单独检查温度换算公式。
Integration Test 集成测试检查模块协作。探针读数能否经过收发台进入档案。
Benchmark 性能基准测试在明确条件下测量性能。每分钟能处理多少读数单、等待多久。
pandasPython 数据处理库。将多次实验记录整理、清洗、汇总。
Data Pipeline 数据流水线一系列可重复的数据处理步骤。原始记录 → 查错 → 标记缺失 → 计算特征 → 比较结果。
Feature 特征从原始数据计算的有用量。不只看每秒温度，还计算平均温度和升温速度。
ADR 架构决策记录记录背景、决定、理由、替代方案、代价及重新评估条件。记下为什么选择冷藏发酵、其他方案、代价和何时重试。
MVP验证核心目标的最小可用版本。先完成一套能测量、保存、查询的实验流程。

你关心的“标签不能当检测结果”，用烘焙很好理解：你提前给实验贴上“成功肉桂卷”，不代表系统真的通过温度、时间和成品数据判断出它成功了。

模拟器的 jump 也是预先安排的标签。检测器要通过运动信号独立判断，最后才能与标签对照。

11 项目怎样保存与协作

技术名字实际含义烘焙类比
Repository 仓库文件及其版本历史。配方、流程、记录的完整档案。
Git版本管理工具。保存每次可追溯修改的方法。
GitHub托管 Git 仓库的平台。双方共同访问的远程档案室。
Branch 分支一条独立演进的提交历史。在基准配方上研究新版本，保留原基准。
Commit 提交一次有说明的版本快照。“本次调整发酵时间，并记录原因”。
Fetch / Pull获取远程信息／获取并整合更新。查看新记录／把新版本同步到本地。
Stash暂存未提交修改。先把桌上的实验草稿收好，再切换工作。
CI/CD自动检查及交付流程。流程修改后自动执行规定检查，通过后再交付。
GitHub ActionsGitHub 提供的自动化执行系统。帮我们运行测试和构建的自动工作岗位。

我们的当前约定是：助手直接在分支中修改和 commit，用户通过 Git 同步；不再反复下载文件，不创建 PR。

名字在未来项目中的用途

Storage保存文件、对象和数据集等。
ESP-IDFESP32 固件开发框架。

对照当前进度：我们已经建立了实验档案和记录单规则，并在 Windows 的 Python 虚拟环境中通过全部 46 项契约检查。接下来安装 Docker，是准备工作室基础设施；再启动 Mosquitto，让第一张模拟读数单真正经过收发台。
