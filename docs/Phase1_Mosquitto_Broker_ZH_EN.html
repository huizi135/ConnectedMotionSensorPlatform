Step A Initialize and start 初始化与启动

进入项目根目录、确认在 phase-1/virtual-sensors 且工作区干净。逐条执行，前一步失败先诊断，不继续依赖步骤。初始化会拉取镜像，生成本地凭据并写入认证卷；尚不启动模拟器。

git pull --ff-only
.\.venv\Scripts\python.exe tools/initialize_mqtt.py
docker compose -f infrastructure/compose.yaml config --quiet
docker compose -f infrastructure/compose.yaml up -d mosquitto
docker compose -f infrastructure/compose.yaml ps
docker compose -f infrastructure/compose.yaml logs --tail 40 mosquitto
git status --short

Expected: the initialization reports success without passwords; mosquitto is running, plugins/listener start without auth-file or permission errors, and git status is clean. 预期：凭据初始化成功且不打印密码；容器运行；插件、监听器启动，无认证文件/权限错误；Git 干净。running 还不等于 MQTT 验收。

Step B Authentication and routing 认证与路由

只在启动日志检查通过后执行：

.\.venv\Scripts\python.exe tools/test_mqtt_broker.py

验证宿主 TCP 端口可达；匿名和错误密码被明确拒绝；后端账号越权发布被拒绝；模拟器角色发布的合法 JSON 被后端角色完整接收。脚本等待真实 SUBACK 再发布，不依赖固定睡眠时间。

The MQTT clients run inside the broker container; host TCP is checked separately. Host-native Python MQTT is a later simulator test. MQTT 客户端测试在容器内执行，宿主端口另行测试；这还不能证明宿主 Python 的 MQTT 链路已成功。测试密码传给短暂客户端进程，仅适用于受信本地开发，不是生产密钥管理。

Acceptance and current limits 验收与当前边界

Current state: files prepared and static checks passed; Windows initialization, broker startup and MQTT smoke results remain pending. 当前仅完成文件与静态检查，不能宣称 Broker 已成功运行。Last Will、retained、重连、持久化故障、真实设备与后端数据库都留待后续分步验证。

PASS: YAML parses; loopback binding; version tag; service users; opt-in offline init; all bind sources exist/read-only; declared volumes; read-only broker auth; Python syntax; POSIX shell syntax/LF; explicit authentication and role ACL structure.
NOT RUN: Docker Compose runtime validation, image execution, password hashing, broker startup, MQTT authorization and routing. No Docker/pwsh/mosquitto executables are available in the assistant environment.

Recovery 故障恢复原则

重复初始化复用本地密码；运行中的 Broker 不修改凭据。若本地凭据丢失但认证卷已存在则拒绝覆盖。端口冲突先查明来源；权限或插件错误保留日志，不改成匿名或 chmod 777。停止时使用 down，不加 -v，以保留卷。不要公开 secrets 文件。
