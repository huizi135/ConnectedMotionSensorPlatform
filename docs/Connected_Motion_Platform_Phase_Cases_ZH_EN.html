Phase 0 Architecture and repository baseline

架构与仓库基线 | Design and test plan 设计与测试计划 | 22 Oct 2026

Architecture 架构

GitHub → Windows clone → contracts and ADRs → future modules

Create an auditable design and reproducible starting point.
建立可审查设计和可复现起点。

ADR P0 Preserve repository history 保留仓库历史

Context 背景 The remote already contains README.md on main.
远程 main 已有 README.md。

Decision 决定 Clone the existing repository and keep bilingual design records.
克隆现有仓库，保留双语设计记录。

Alternatives 替代 Initialize locally and merge histories; start a new repository.
本地初始化再合并历史；另建仓库。

Rationale and cost 理由与代价 Cloning preserves history and tracking; HTML needs synchronized Markdown for reviewable diffs.
克隆保留历史和跟踪；HTML 需同步 Markdown 以便审查差异。

Revisit 重新评估 Reconsider structure if teams or independently released components emerge.
出现团队协作或独立发布模块时再评估结构。

Recovery 错误恢复 If the destination exists, inspect it; if authentication fails, diagnose the exact error. Never overwrite or force-push.
目标存在则检查；认证失败保留原错误。避免覆盖或强制推送。

Data reliability 数据可靠性 Versioned contracts define identities, units and time semantics before ingestion code exists.
接收代码前先定义版本、身份、单位及时间语义。

Tests 测试方法 Verify clean status, origin URL, main tracking and initial commit; review schema examples and failure assumptions.
核实干净状态、origin、main 跟踪和初始提交；评审契约示例及故障假设。

Evidence and exit gate 证据与验收 Git, schema checks and Windows baseline synchronization verified; f8bfed5, clean tracking branch.
Git、契约校验与 Windows 基线同步已验证；f8bfed5，跟踪分支且工作区干净。

Phase 1 Virtual IMU and MQTT communication

虚拟 IMU 与 MQTT 通信 | Design and test plan 设计与测试计划 | 22 Oct 2026

Architecture 架构

Python devices → Mosquitto → contract verifier

Generate reproducible multi-device signals with inspectable transport.
生成可复现多设备信号，验证传输。

ADR P1 Readable sample messages 可读采样消息

Context 背景 Python and .NET will share a protocol; no hardware exists.
跨 Python/.NET 协议，无硬件。

Decision 决定 JSON, one sample per message; telemetry QoS 1 without retain; retained status and a Last Will.
JSON 单样本；读数 QoS 1 不保留；状态保留并设置遗嘱。

Alternatives 替代 Batch binary frames, BLE-first simulation or file replay.
二进制批次；先模拟 BLE；文件回放。

Rationale and cost 理由与代价 Easy diagnosis and schema testing; more metadata overhead and no complete offline replay.
便于诊断与契约测试；元数据较多，不保证完整离线补传。

Revisit 重新评估 Measure batching/encoding options when required sampling rates exceed the tested envelope.
目标采样率超出实测范围时比较批次与编码。

Recovery 错误恢复 Reconnect with controlled retry; publish online after connection and offline before graceful exit.
受控重试连接；连接后发 online，正常退出前发 offline。

Data reliability 数据可靠性 Keep sample IDs on retries; separate connection IDs from sampling streams; stale status needs timeout checks.
重试保留样本 ID；连接与采样流分开；超时检查过时状态。

Tests 测试方法 Three devices for five minutes; fixed seeds; validate schemas and sequences; kill a client and restart the broker.
三设备五分钟；固定种子；验证契约序列；强制退出及重启 Broker。

Evidence and exit gate 证据与验收 Planned; record rates, messages, gaps and reconnect time after execution.
待执行；记录速率、消息量、缺口与恢复时间。

Phase 2 Backend persistence and query API

后端持久化与查询 API | Design and test plan 设计与测试计划 | 22 Oct 2026

Architecture 架构

MQTT adapter → bounded queue → processor → PostgreSQL ← API

Persist valid samples once and expose bounded historical queries.
合法样本去重保存，提供受限历史查询。

ADR P2 Database idempotency 数据库幂等

Context 背景 QoS 1 and retries can redeliver a sample.
QoS 1 与重试可能重复投递。

Decision 决定 Use unique message and stream/sequence identities, transactions and explicit conflict handling.
唯一消息及流序号约束、事务与显式冲突处理。

Alternatives 替代 Memory deduplication only; QoS 2 alone; external event storage.
仅内存去重；仅 QoS 2；外部事件存储。

Rationale and cost 理由与代价 Database constraints survive restarts; add indexes and write cost, without making MQTT acknowledgment a commit.
约束跨重启有效；增加索引写入成本，MQTT 确认仍不等于提交。

Revisit 重新评估 Measure independent ingestion deployment or batching if writes interfere with API targets.
写入影响 API 目标时评估拆分或批量写入。

Recovery 错误恢复 Retry transient database failures with limits, apply backpressure, and reject malformed messages observably.
数据库瞬时故障有界重试并背压；非法消息拒绝且可观察。

Data reliability 数据可靠性 Document commit/ack behavior from actual MQTTnet tests; in-memory queued samples can be lost on exit.
实测记录 MQTTnet 提交确认行为；退出可能损失内存样本。

Tests 测试方法 Redeliver a sample, change conflicting content, reorder samples, stop the database and test stable pagination.
重复、冲突、乱序、停数据库与稳定分页集成测试。

Evidence and exit gate 证据与验收 Planned; retain SQL counts, failure logs and test reports.
待执行；保存 SQL 计数、故障日志与测试报告。

Phase 3 Deployment and observability

部署与可观测性 | Design and test plan 设计与测试计划 | 22 Oct 2026

Architecture 架构

Compose services → structured logs and metrics → Prometheus → Grafana

Reproduce startup and distinguish failure causes.
复现启动，并区分故障原因。

ADR P3 Bounded metric labels 限制指标标签基数

Context 背景 Per-device metric labels can grow with the fleet.
按设备的指标标签随设备数膨胀。

Decision 决定 Use aggregate metrics with bounded labels; put message/device IDs in structured logs or database queries.
聚合指标采用有限标签；消息与设备 ID 放日志或数据库查询。

Alternatives 替代 A time series per device; logs only; hosted monitoring.
每设备时序；只用日志；托管监控。

Rationale and cost 理由与代价 Controls monitoring cost; individual device diagnosis needs correlated logs or queries.
控制监控成本；单设备诊断需关联日志和查询。

Revisit 重新评估 Add a bounded selected-device view if operational evidence requires it.
实际运维需要时增加受控设备视图。

Recovery 错误恢复 Persist service data and distinguish live from ready; restart policies do not replace reconnect logic.
持久化服务数据，区分 live 与 ready；重启策略不代替重连。

Data reliability 数据可靠性 Observe received, committed, rejected and duplicate counts separately; define each latency boundary.
区分接收、提交、拒绝及重复计数，定义延迟测量边界。

Tests 测试方法 Start from a clean environment; restart services; check ready failures and resumed metric scrapes.
新环境启动；重启服务；验证 ready 异常及指标恢复。

Evidence and exit gate 证据与验收 Planned; save Compose config, dashboard JSON and a repeatable run log.
待执行；保留配置、Dashboard JSON 和运行记录。

Phase 4 Reliability and capacity experiments

可靠性与容量实验 | Design and test plan 设计与测试计划 | 22 Oct 2026

Architecture 架构

Fault/load generator → MQTT → backend → durable storage → reconciliation

Quantify failure windows and capacity under stated conditions.
量化特定条件下的故障窗口与容量。

ADR P4 Measured durability guarantees 以测量定义持久化保证

Context 背景 Protocol delivery alone cannot prove successful persistence.
协议投递无法单独证明持久化。

Decision 决定 Reconcile stable sample IDs against committed rows and define the accepted loss and recovery envelope.
用稳定样本 ID 对账入库，明确允许丢失与恢复范围。

Alternatives 替代 Assume QoS is sufficient; immediately add durable spooling and application acknowledgments.
假设 QoS 足够；立即增加磁盘缓冲与应用确认。

Rationale and cost 理由与代价 Evidence drives complexity; baseline failures may demonstrate loss before a stronger design is implemented.
证据驱动复杂度；增强设计前可能观察到基线丢失。

Revisit 重新评估 Add durable buffering/acknowledgments if observed loss exceeds the agreed requirement.
丢失超出明确需求时增加持久缓冲及确认。

Recovery 错误恢复 Inject disconnects, broker/database outages and process crashes; verify retry bounds and recovery time.
注入断线、Broker/数据库故障和崩溃；验证重试上限与恢复时间。

Data reliability 数据可靠性 Track generated, sent, acknowledged and committed IDs separately; allow a defined late-arrival window.
分别追踪生成、发送、确认及提交 ID，规定迟到等待窗口。

Tests 测试方法 Sweep 100–1,000 devices at specified rates; measure throughput, P95/P99 delay, resources, gaps and duplicates.
指定频率测试 100–1000 设备，测吞吐、尾延迟、资源、缺失与重复。

Evidence and exit gate 证据与验收 Planned; report hardware, versions, seeds, duration and before/after results.
待执行；记录硬件、版本、种子、时长与优化对比。

Phase 5 Data quality and motion analytics

数据质量与运动分析 | Design and test plan 设计与测试计划 | 22 Oct 2026

Architecture 架构

Raw observations → quality checks → features → detector → label evaluator

Create traceable analytical data and independently evaluated events.
生成可溯源分析数据与独立评估事件。

ADR P5 Isolate reference labels 隔离参考标签

Context 背景 Simulator scenario labels reveal the answer and can leak into inference.
场景标签暴露答案，可能泄漏到推断。

Decision 决定 A typed detector input contains observations only; join reference intervals after predictions.
检测输入类型仅含观测；预测后再关联参考区间。

Alternatives 替代 Read scenario directly; keep unrestricted envelopes; train a supervised model with proper splits.
直接读场景；不限制输入；正确划分数据后训练监督模型。

Rationale and cost 理由与代价 Tests measure the detector rather than label copying; independent interval matching adds work.
评估检测而非抄标签；独立区间匹配增加工作。

Revisit 重新评估 Consider learned models only with appropriate labeled data and independent validation; preserve inference isolation.
有适当标注及独立验证时考虑学习模型，仍保持推断隔离。

Recovery 错误恢复 Rerun deterministic transformations using raw data and pipeline versions; quarantine invalid records.
用原始数据和版本重跑确定性转换，隔离无效记录。

Data reliability 数据可靠性 Retain lineage, gaps and quality flags; never silently fill missing events as observed facts.
保留溯源、缺口和质量标记，不把填补事件伪装为观测事实。

Tests 测试方法 Shuffling labels must not change predictions; evaluate event precision/recall and timing on held-out runs.
打乱标签预测不变；独立流评估事件 precision/recall 与时间误差。

Evidence and exit gate 证据与验收 Planned; synthetic results do not establish real-world recognition accuracy.
待执行；合成结果不证明真实识别准确率。

Phase 6 Optional hardware and cloud adaptation

可选硬件与云扩展 | Design and test plan 设计与测试计划 | 22 Oct 2026

Architecture 架构

ESP32 IMU → BLE Gateway → MQTT → unchanged backend contract

Replace the source without coupling analytics to device transport.
替换来源，保持分析与设备传输解耦。

ADR P6 Gateway normalization 网关规范化

Context 背景 Real BLE frames, units and clocks differ from the simulator.
真实 BLE 帧、单位与时钟不同于模拟器。

Decision 决定 Normalize at the Gateway and preserve source sample identity during buffering and replay.
在网关规范化，缓冲重放时保留来源样本身份。

Alternatives 替代 Direct Wi-Fi/cloud firmware; normalize inside the backend; redesign the contract.
固件直连 Wi-Fi/云；后端转换；重新设计契约。

Rationale and cost 理由与代价 Backend reuse reduces change; the Gateway becomes an operational and security dependency.
复用后端减少改动；网关成为运维与安全依赖。

Revisit 重新评估 Reconsider for power, latency, fleet management or cloud identity requirements.
功耗、延迟、设备管理或云身份需求变化时评估。

Recovery 错误恢复 Test BLE disconnects, Gateway restarts, credentials and network outages; design OTA rollback separately.
测试 BLE 断线、网关重启、凭据和网络故障；OTA 回滚另行设计。

Data reliability 数据可靠性 Verify clock quality, axes, units and sample IDs; distinguish pairing security from cloud authentication.
验证时钟、坐标、单位和 ID；区分配对安全与云认证。

Tests 测试方法 Compare stationary/controlled-motion readings, reconnect replay and end-to-end persistence with real hardware.
真实硬件测试静止、受控运动、重连补传及端到端入库。

Evidence and exit gate 证据与验收 Optional and unstarted; requires hardware and a separately approved implementation scope.
可选且未开始；需要硬件并另定实施范围。
